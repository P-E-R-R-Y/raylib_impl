Detailed Description

Raylib Model class - references a RayMesh, does not own it.

KNOWN NON-CONFORMANCE : raylib::UpdateModelAnimation() writes the pose into the mesh's own vertex buffer. Two RayModel sharing one RayMesh cannot sit on two different animation frames at the same instant - the last updateAnimation() called wins. The contract wants the opposite ; raylib is what falls short. Sharing position/rotation/size works. Deleting the model never touches the mesh, texture or animation set it was built from/bound to.

Note: raylib::UpdateModelAnimation() writes the pose into the mesh's own vertex buffer, so two RayModel instances sharing one RayMesh cannot be at two different animation frames at the same instant - a real raylib constraint, not something this wrapper works around.
